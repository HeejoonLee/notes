# Keep the `repo` tool and Manifests; replace Gerrit-style push with merge requests

The Google `repo` tool and its Manifests stay as the way to assemble a Workspace. It is host-agnostic, and only `repo upload` depends on Gerrit. Git submodules were rejected: they can't give each Audience a different subset of repos, and a parent repo would leak Restricted repo SHAs to Item developers. Pushing to `refs/for/master` is dropped entirely. Every change goes through a GitLab merge request into `main`, merged fast-forward with squash so history stays linear with one commit per change, as under Gerrit. Gerrit stays read-only as an archive of old review comments (except for the kernel, see ADR 0003). There is deliberately no wrapper command around push: people use plain `git push` and GitLab MRs, the standard workflow they will meet elsewhere.
